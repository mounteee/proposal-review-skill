# proposal-review

一个用于 Claude Code 的方案审核 Skill，通过多视角审稿机制检查方案的逻辑链、事实证据、结构说服力和可执行性，输出可追责、可修改的审核报告。

## 适用场景

- 市场策略方案、增长方案、商业论证
- 客户提案、销售材料、对外发布内容
- 课程大纲、活动策划
- 任何需要在发布或决策前接受严格审查的文本

## 触发方式

在 Claude Code 对话中，把方案内容粘贴进来，然后说：

```
审核这份方案
方案审稿
review proposal
框架审核 / 内容审核 / 数据来源审核
```

## 审核机制

每次审核分四个阶段：

**1. 输入归一**：提取方案的标题、受众、用途、核心论证链、数据来源和隐含假设，缺失信息以"默认假设"标记，不中断审核流程。

**2. 独立审稿**：五个角色各自基于原文独立审核，互不参考：

| 角色 | 审查重点 |
|---|---|
| 严谨逻辑学家 | 概念定义、前提推理、结论边界 |
| 演化经济学家 | 竞争识别、激励结构、路径依赖、市场反身性 |
| 证据与数据审计员 | 数字来源、数据口径、案例代表性 |
| 目标用户 / 决策者代理 | 读者视角、信任路径、行动指引 |
| 红队反方审稿人 | 最强反例、最脆弱处、执行失败风险 |

**3. 交叉质询**：区分多视角共识问题（高优先级）、单一视角高风险问题和冲突意见，按证据强度仲裁。

**4. 综合输出**：改写成可执行修改报告，不堆叠原始审稿意见。

## 输出结构

```
1. 最终结论（可发布 / 小修后可用 / 需大修 / 不建议发布）
2. Top 3-5 问题（含原文证据、严重性、修改方向）
3. 逻辑链审核
4. 事实与数据来源审核表
5. 框架结构审核
6. 演化经济学视角
7. 反方压力测试
8. 逐段修改建议
9. 评分表（6 个维度，各 1-5 分）
10. 发布前 checklist
```

长方案默认先输出结论、Top 问题、证据缺口表和 checklist，输入"展开"后输出完整报告。

## 评分维度

| 维度 | 说明 |
|---|---|
| 逻辑严密性 | 概念定义、推理链完整性、结论边界 |
| 证据强度 | 来源质量与覆盖率 |
| 框架清晰度 | 结构是否服务目标、层级是否清楚 |
| 受众说服力 | 是否回应目标受众的动机和疑虑 |
| 策略可执行性 | 动作、资源、时序、指标是否清楚 |
| 风险意识 | 反例、失败条件、替代解释的覆盖程度 |

最终结论按短板决定，不简单平均。

## 安装

把整个 `proposal-review/` 目录放入你的 Claude Code skills 目录：

```
~/.claude/skills/proposal-review/
```

重启 Claude Code 后 skill 自动加载。
